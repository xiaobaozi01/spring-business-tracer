# V2.0 配置依赖感知的保守增量分析

增量基线必须满足：schemaVersion=2.0、phase=COMPLETE、存在 graphHash、topologyRootHash、manifestHash 与不可变快照。V0.5/V1.0/V1.5、PARTIAL、STALE 或缺少任一根的baseline均不可复用。

INCREMENTAL审计必须同时绑定`baseGraphHash`、`baseManifestHash`和`baseTopologyRootHash`，并通过`CONFIG_DEPENDENCY_CLOSURE`。插件会重算changedConfigKeys和各互斥集合；报告缺根、配置依赖未闭合或集合不精确时拒绝seed。

当前run必须全量重发现入口。插件比较serviceSnapshots得到changedServices，并比较resolutionSummary得到changedConfigKeys；未解析项的比较同时包含reason和安全sourceHash。旧入口只有serviceClosure不含变化服务、configDependencyIds不含变化键或任一基线/当前unresolved键、无shared/unowned依赖且工件哈希有效时才可复用。配置依赖缺失时保守重算。

incremental validator独立计算 `changedServices/changedConfigKeys/reusableEntryIds/affectedEntryIds/newEntryIds/tombstonedEntryIds/workQueueEntryIds`，绑定baseline根后提交。插件再次计算并要求完全相等、互斥、闭合。rename一律是旧ID tombstone加新ID。

tombstone 只有在全量入口覆盖审计通过且新 run 最终 COMPLETE 后才成为正式删除结论；PARTIAL/FAILED/STALE 不发布 tombstone。服务从配置 scope 移除要求 FULL_REBASE/OUT_OF_SCOPE，不能当删除。节点/边只有不再被任何当前入口引用时才进入 tombstone。复用文档从 baseline immutable snapshot复制到新 staging；图仍从复用的原始trace与新trace重新确定性构建。
