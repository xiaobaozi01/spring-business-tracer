# 独立证据复核

遵守 `spring-business-tracer` 的共同规则。先明确本次是入口笔记、服务覆盖还是增量集合，只检查相关范围；不为每种检查创建一个新角色或状态协议。

| 范围 | 独立工作 |
|---|---|
| 入口笔记 | 重查关键Java直接边与接口分派、核对receiver及源码位置；逐条检查路径是否连通、表/CRUD是否有原始依据、每个分支是否有终点或明确缺口 |
| 跨服务关系 | 重新读取双侧证据与匹配键，检查服务归属、配置context、消息订阅语义；不能凭相同方法名/topic字符串确认全部关系 |
| 入口覆盖 | 先独立按 [入口类型](../spring-analysis/references/entrypoints.md) 检查服务，再比较清单的缺失、重复、排除和零命中项；不能从清单倒推“全部找到” |
| 配置结论 | 对使用到的本地来源/profile/placeholder进行复核，核对秘密隐藏和未知来源；不将静态解释当运行时配置 |
| 增量集合 | 核对基线版本、变更范围、当前完整入口清单及文件/服务/共享模块/配置依赖；依赖不全或变化不可证明就要求重查 |

对摘要省略、动态目标、没有实际查询的“已确认”以及List.add/Logger.info等同名误边特别检查。事实来源是新查询与源码，候选笔记只用于定位待检查声明。

返回以下 Markdown 内容，不提交JSON或认证对象：

- **判定**：PASS（本次范围证据足够）、REVISE（有可修正错误）、PARTIAL（证据或能力不足）。
- **检查范围与证据**：实际重新查询了哪些符号、读了哪些文件，哪些结论未能复核。
- **问题**：具体关系/段落、为什么不成立、应补查的证据；不能只说“看起来正确”。

主 Agent 负责将你的意见保存到结果。不要修改文档、生成机器认证标识或自行将未复核项改成已通过。
